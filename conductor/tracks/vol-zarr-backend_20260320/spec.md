# Specification: Zarr Volume Backend

**Track ID:** vol-zarr-backend_20260320
**Type:** Feature
**Created:** 2026-03-20
**Status:** Draft

## Summary

Implement a `ZarrVolume` backend that reads volumetric data from the Zarr v2/v3 chunked array format, providing parallel chunk-level IO and better cache locality compared to the per-slice TIFF model.

## Context

The existing `TIFFVolume` stores each Z-slice as a separate TIFF file. For texturing algorithms that sample neighborhood regions (cuboid or line neighborhoods along surface normals), the access pattern scatters across many slices. Each cache miss opens a separate file and reads a full slice (potentially 16–64 MB) to retrieve a handful of voxels. Zarr stores data in small N-dimensional chunks (e.g., 128×128×128 voxels) with optional compression, so a neighborhood-shaped access retrieves only the relevant chunks — typically 1–8 chunks instead of N full slices. This dramatically reduces IO amplification and enables true parallel chunk loading.

Depends on `vol-abstract-iface_20260320` (ZarrVolume implements the `Volume` interface).

## User Story

As a researcher processing large CT volumes, I want to convert my `.volpkg` TIFF volume to Zarr format once and then run texture generation significantly faster, because neighborhood sampling reads only the needed data chunks rather than entire slice files.

## Technical Notes

**Zarr library options:**
- [`zarr-cpp`](https://github.com/zarr-developers/zarr-cpp) — official C++ implementation (in development, may be immature)
- [`z5`](https://github.com/constantinpape/z5) — mature, header-only, supports Zarr v2 + N5, used in neuroscience pipelines; recommended
- [`xtensor-io`](https://github.com/xtensor-stack/xtensor-io) — depends on xtensor

Recommendation: `z5` via FetchContent. It's header-only, has no heavy dependencies beyond `blosc`/`zlib` for compression, and is battle-tested on large EM volumes (similar use case).

**On-disk layout in `.volpkg`:**
```
volumes/{id}/
  meta.json          (existing)
  slices/            (existing TIFF files)
  zarr/              (new — Zarr array root)
    .zarray
    0.0.0, 0.0.1, ...  (chunks)
```

**`getSliceData()` on ZarrVolume:** Read the full XY plane at Z=index by reading all chunks that intersect that plane. This preserves API compatibility for code that iterates slices.

**Chunk size recommendation:** 128×128×128 for typical scroll CT resolutions; expose as a conversion parameter.
