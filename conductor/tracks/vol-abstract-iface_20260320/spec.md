# Specification: Volume Abstract Interface

**Track ID:** vol-abstract-iface_20260320
**Type:** Refactor
**Created:** 2026-03-20
**Status:** Draft

## Summary

Extract a pure virtual `Volume` base class from the current monolithic concrete `Volume` (TIFF-backed) implementation, and rename the TIFF-specific class to `TIFFVolume`. All existing call sites adopt the base class pointer type.

## Context

The current `Volume` class in `core/include/vc/core/types/Volume.hpp` is simultaneously the public API and the TIFF-slice-stack implementation. Every algorithm, app, and test that samples the volume is coupled to this single backend. Introducing alternative backends (Zarr, HDF5, in-memory) requires a clean interface separation first. This track is the foundation for `vol-zarr-backend_20260320`, `vol-cache-parallel_20260320`, and `texturing-parallel_20260320`.

## Acceptance Criteria

- [ ] A pure virtual `Volume` base class exists in `core/` exposing all public sampling and metadata methods
- [ ] `TIFFVolume` is a concrete subclass of `Volume` containing all existing TIFF/LRU/mmap implementation
- [ ] All existing call sites (apps, texturing, segmentation, graph, utils) use `Volume::Pointer` (base type)
- [ ] `VolumePkg` creates and returns `TIFFVolume` instances as `Volume::Pointer`
- [ ] All existing unit tests pass without modification
- [ ] No behavior change: this is a pure refactor

## Out of Scope

## Technical Notes

The current `Volume` public interface to preserve in the abstract base:
- Metadata: `sliceWidth()`, `sliceHeight()`, `numSlices()`, `voxelSize()`, `bounds()`
- Sampling: `getSliceData(int)`, `getSliceDataCopy(int)`, `intensityAt(x,y,z)`, `interpolateAt(x,y,z)`, `reslice(...)`
- Cache control: `setCacheSize()`, `setCacheMemoryInBytes()` — consider whether these belong on the base or only on `TIFFVolume`

`Volume::Pointer` is likely already `std::shared_ptr<Volume>` via an ITK-style `using Pointer = std::shared_ptr<Volume>` — verify and preserve this pattern on the base class.
